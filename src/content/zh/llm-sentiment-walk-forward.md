把大模型接入量化项目时，最直接的想法是问它：“这只股票会涨还是会跌？”这个问题很诱人，因为回答看起来像最终决策。但对初学者来说，它也最难验证：模型可能引用了错误事实，时间边界可能混乱，同样的提示词还可能在不同版本下给出不同结论。

更麻烦的是，这种问法把两件事混在了一起——一是从文本里读出发生了什么，二是判断这件事对价格意味着什么。前者是语言理解，模型确实擅长；后者是带着成本、时滞和风险的决策，应该由能被回测检验的规则来承担。把它们捆在一句提问里，等于放弃了单独验证每一步的机会。

我后来选择了一条更克制的路径：让大模型做信息抽取，而不是直接控制仓位。

## 把文本变成可审计事件

一条新闻或公告进入系统后，先保存原文、来源链接、发布时间和内容哈希。模型读取文本，输出：

- 利好、中性或利空标签；
- 归一化分数；
- 置信度；
- 摘要和判断理由；
- 模型名称与分析时间。

这些字段不会覆盖原始新闻，而是形成独立的派生数据。将来更换模型或提示词时，我可以重新分析，并比较不同版本对同一条文本的理解。

区分“原文”和“派生数据”是我反复强调的一条纪律。原文是不可变的证据，它带着自己的发布时间；派生数据是可重算的解释，它带着模型名和分析时间。一旦把模型的判断直接写回原文字段，就再也说不清某个分数到底是哪一版模型、在什么时刻给出的——而这恰恰是回测里最需要追问的东西。理由字段（reason）也不是装饰：当某条样本外交易出乎意料时，我能顺着这条理由回到原文，判断是模型看错了事实，还是事实本身没有价值。

大致的输出契约可以写成这样，字段固定、便于后续做结构校验：

```json
{
  "event_id": "sha1(raw_text)",
  "published_at": "2026-03-11T09:20:00Z",
  "source_url": "https://…",
  "label": "bullish",          // bullish | neutral | bearish
  "score": 0.62,               // 归一化到 [-1, 1]
  "confidence": 0.71,          // [0, 1]，示例值
  "summary": "……",
  "reason": "……",             // 可复查的判断依据
  "model": "llm-vX",
  "analyzed_at": "2026-03-11T09:24:10Z"
}
```

这一步最大的价值并不是“AI 很聪明”，而是把自然语言判断转换成可以筛选、聚合、测试和质疑的数据。一个只会说“看多”的黑箱没法回测，一张带时间戳、带来源、带置信度的事件表可以。

## 时间仍然是第一条纪律

新闻的发布时间必须早于策略做决定的时间。这句话听起来是常识，实现时却处处是坑：抓取时间不等于发布时间，同一条公告在不同平台的落地时刻可能相差几小时，而回测里只要错用了“我抓到它”的时刻而不是“它公开”的时刻，就会悄悄引入未来函数。

重复转载需要去重，同一事件的多篇报道不能被当成多次独立利好。内容哈希在这里就派上用场：近似相同的正文合并为一个事件，不同媒体的转发只是同一事件的多个副本，而不是三条独立信号。如果不去重，一条被大量转载的消息会在情绪分上被反复计数，制造出虚假的“共识强度”。

情绪也不是永久有效的：七天前的消息通常不应和刚刚发布的公告拥有相同权重。因此，系统按照事件时间构建衰减窗口，让权重随消息变旧而下降，再按股票聚合情绪分。一个示意性的做法是给每个事件一个指数衰减权重（下式仅为示例，半衰期需要在训练段里选，不能拿测试段来凑）：

```text
w(t) = exp(-λ · Δt)          # Δt = 决策时刻 − 事件时刻（天）
score_stock = Σ_i  w(t_i) · confidence_i · score_i   （对该股所有事件求和）
```

![情绪的时间衰减窗口：权重随事件变旧而下降，并对同一事件的多篇报道去重](/images/llm-sentiment-decay.svg)

任何回测都要明确三个时刻：新闻何时可见、何时进入因子、何时影响下一周期仓位。我习惯把它们分开记录，而不是笼统地说“用了这条新闻”。只要时间顺序错了，再精确的文本分类也只是在制造未来函数。

## 比较“有 AI”和“没有 AI”

标签准确并不代表具备交易价值。模型可以把一条公告的情绪判断得很准，但如果这份信息早已反映在价格里，或者它带来的超额收益不足以覆盖换手成本，那么它对策略就是没有增量的。要回答“有没有用”，只能做对照实验。

我的实验会先建立只使用行情与财务因子的基线，再加入情绪因子，并在**相同股票池、相同成本、相同窗口**下比较。控制变量是这里的关键：两组唯一的差别只能是情绪因子本身，否则赢了也不知道赢在哪。对照维度包括：

| 维度 | 基线（无 AI） | 加入情绪因子 | 我关心的问题 |
| --- | --- | --- | --- |
| 样本外累计 / 年化收益 | 参照 | 对照 | 增量是否为正 |
| 最大回撤 / 波动 | 参照 | 对照 | 是否用更大波动换收益 |
| 换手 / 额外成本 | 参照 | 对照 | 增量能否覆盖成本 |
| 不同市场阶段 | 参照 | 对照 | 是全程有效还是只在某段 |
| 调用成本 / 延迟 / 失败回退 | — | 需评估 | 工程代价是否划算 |

表中不填具体数字是有意的：这些值要由每一次预先设计好的实验给出，而不是先写一个好看的结论再去凑。最后一行常被忽略——大模型调用有成本、有延迟，也会失败，需要有回退路径（比如降级为中性分或沿用上一次结果），这部分开销同样要算进“有 AI”的账里。

如果加入情绪后只改善训练期，却在多数测试窗口变差，那么结论不是继续调整到曲线好看，而是承认当前因子可能没有稳定增量。

## Walk-forward 让我接受不完美的结果

每个 Walk-forward 窗口包含训练段和随后的测试段。参数只能在训练段选择；测试段只允许运行一次锁定方案。最终结果只拼接各段样本外收益。它的好处在于逼近真实交易的信息节奏：在每个时点，你只能用当时已知的数据做决定，而不能借用未来才出现的规律。

这里有一条我踩过的暗线：测试段只能看一次。如果我因为某个窗口表现差就回去改衰减参数、再重跑同一段测试，那这段“样本外”就已经被我看过、被我用来调参了，它悄悄变成了训练集的一部分。样本外之所以有说服力，正是因为它在被评估之前对策略保持“陌生”。

这套流程让我更愿意保留失败窗口。过去我会把它们看成模型的瑕疵，现在我更愿意问：是市场状态变化、衰减周期不对、文本来源偏差，还是情绪因子本来就没有足够强的经济含义？这几种原因指向完全不同的下一步，而不能笼统归为“模型不行”。

“8 个窗口中 6 个为负”是事实；“模型不够大”只是解释。事实和解释之间隔着一次实验：解释必须等待下一次预先设计的新实验来检验，而不能反过来修改已经看过的测试集。把解释当成结论，是我最容易犯、也最难自查的错误。

## 我的当前结论

大模型在量化系统里最适合承担可追踪的信息整理、分类和研究辅助。仓位与风险控制仍应由明确规则负责，最终价值必须通过样本外结果和成本检验。让模型待在“把文本变成可审计数据”这一格里，它的贡献才是可加、可减、可复现的。

克制并不会削弱 AI。相反，给它一个边界清晰、能够被验证的职责，才让我知道它究竟贡献了什么。

这些方法正在 [AI 量化系统](/quant/) 的研究闭环中持续验证。
