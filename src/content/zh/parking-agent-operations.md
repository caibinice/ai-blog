三维停车场已经具备精细园区、车辆巡行、轮胎转动和固定尾随。下一步要解决的是业务：访客去哪里停车，安保怎样核验告警，运营如何解释收入与利用率，以及助手怎样把语言请求落实到具体界面。

这次扩展仍然保留全屏操作。聊天和业务台是可隐藏浮层，不压缩三维画布；后端继续复用企业智能座舱的 Spring Boot 服务、MySQL、pgvector 和知识检索，没有再部署一个智能体服务。

## 先建立可追溯的年度数据

真实停车设备数据暂时难以采集，先用公开数据提取规律，再生成适配本项目的年度合成账本。参考的是 [UCI Parking Birmingham](https://archive.ics.uci.edu/dataset/482/parking%2Bbirmingham)：原始样本来自 Birmingham City Council/NCP，由 Daniel Stolfi 整理，覆盖2016年部分日期的日间时段，并不是完整全天数据。仓库保留来源、原文件哈希及许可说明。

生成器清洗无效容量与越界占用，按工作日、周末及十五分钟时间槽提取占用率。夜间使用明确的合成曲线，再加入季节变化、分区系数和固定随机种子。合成数据覆盖 **2025-10-03 至 2026-10-02，共365天**。

| 数据 | 数量 | 主要用途 |
|---|---:|---|
| 十五分钟分区占用快照 | 105,120 | 利用率、余位、历史趋势 |
| 匿名停车记录 | 167,906 | 入场、离场、停留与收费账本 |
| 合成运行告警 | 365 | 巡检、工单及权限验证 |

A/B/C容量分别为120、100和80。每个分区的相邻采样点满足守恒关系：

```text
本次占用 = 前次占用 + 本次入场 - 本次离场
0 <= 占用 <= 容量
```

入场创建匿名停车记录，离场结算对应记录。金额以“分”保存，使用单独的模拟收费规则。原数据没有收费字段，合成费用也不代表任何真实医院价格。最终收入来自 `paid_cents`，而不是占用车辆乘一个估计客单价。

```sql
SELECT COUNT(*) AS settled_stays,
       COALESCE(SUM(paid_cents), 0) AS paid_cents
FROM parking_stays
WHERE dataset_id = 'parking-year-v1'
  AND exited_at >= :from
  AND exited_at < :to_exclusive;
```

生成器记录源文件SHA256、种子和日期范围，固定输入可以重复生成相同结果。导入前备份数据库，使用不可变数据集ID与幂等主键，导入后校验行数。页面始终显示合成来源与采样时刻，历史数据不伪装成现场实时读数。

## 把权限落实到业务接口

前端按钮只是体验入口，权限边界放在后端。所有停车业务GET和写接口都解析服务端签名身份；命名账号的角色还会回查数据库。密码只保存BCrypt哈希，会话令牌有效期30分钟。

| 角色 | 可用业务 |
|---|---|
| 访客 | 泊位、联合推荐、POI、路径、访客导览、本地知识指南 |
| 安保 | 增加告警、出入、工单提交/领取/核验、场景截图分析 |
| 运营 | 增加经营账本、日周月年报、全局审计、工单审批与关闭 |
| 管理员 | 增加业务账号、知识初始化与道路图配置 |

访客自由问答不调用付费模型。业务账号默认使用 Flash 与 `thinking max`，Pro 仍作为已验证账号的可选模型。修改浏览器中的role字段不提升权限，账号停用后原令牌也失效。

## 用道路图承接定位与推荐

语言模型只输出稳定POI ID，不输出任意坐标。道路图保存点位、类型、分区、模型坐标、设施能力与关闭状态；保存时检查节点唯一、端点合法、坐标范围和乐观版本号。

路径采用Dijkstra，只经过开放节点与道路。距离按模型比例估计，界面明确标注；关闭或不连通时返回错误，不绘制一条穿越建筑的“伪导航线”。图由管理员维护，后续接入测绘数据时可以替换配置而不修改对话协议。

推荐先过滤满位、关闭、不可达和偏好不匹配的停车区，再结合步行距离、可用空余与急诊模拟预留评分。充电偏好筛选B区，急诊偏好优先C区；普通需求在C区预留10位。每个候选展示余位、距离、预留与推荐理由。特殊设施是分区演示能力，尚不是单泊位传感器读数。

## 工单采用明确的人工确认链

助手的 `workorder.prepare` 只产生草稿。核验告警、填写备注、勾选确认后，人员才能提交数据库写入。状态机为：

```text
待审核 → 运营批准 → 安保领取 → 完成核验 → 运营关闭
```

创建请求携带幂等键，重复提交返回原工单；同一告警已有未关闭工单时避免再建。流转在事务内锁定记录并检查版本号，过期版本返回冲突。模型没有绕过审批或直接控制道闸的工具。

审计记录区分模型计划与实际软件动作。相机工具的反馈标注 `client-result`，表示浏览器报告的结果，不被包装成现场设备回执。

## 经营分析建立在收费账本上

业务台支持年度范围内按日期和分区查询，展示日平均占用率、已结算记录和模拟已收金额。图表使用容量加权，不把三区占用率简单平均；CSV包含全部每日汇总，页面的前18行只是预览。

![一年合成停车账本的经营分析](/images/parking-agent-year-report.png)

日、周、月、年报以数据集最近日期为基准，日为最近一日，周为七日，月为当前数据月份至该日，年为完整365天。座舱现有进程在北京时间 **02:15** 生成四种汇总缓存，仅运行数据库聚合，不产生模型调用。缓存同时保留数据范围和生成时间。

## AG-UI作为交互边界

新的 `/api/parking/ag-ui` 使用标准运行、文本、工具调用和状态快照事件。业务报表、路线、工单草稿及知识引用通过具名CUSTOM事件传递。前端使用 `@ag-ui/core` 官方schema验证每条事件，再经过本地工具白名单执行。

```json
{
  "type": "TOOL_CALL_ARGS",
  "toolCallId": "action-0",
  "delta": "{\"target\":\"outpatient\"}"
}
```

这层适配实现了本项目实际产生的事件集合，不伪造未执行的工具结果。Nginx对该SSE接口关闭缓冲与缓存，先发运行事件，再等待模型规划；前端取消请求后不执行后续场景动作。一次回答可展示多张报表，不让后一张覆盖前一张。

## 语音和视觉都保留显式控制

单次语音、唤醒词和连续对话共用相同业务工具。连续模式保持监听，播报时使用“停车助手”打断；匹配自身播报文本以减少回声误触发。麦克风默认关闭，切换到后台会停止监听。

识别与播报使用浏览器SpeechRecognition/speechSynthesis，实际能力受浏览器、麦克风和网络影响。回归测试验证打断、暂停与释放逻辑；不把合成识别事件等同于真人识别准确率。

视觉页面先截取三维画布并预览，人员确认后才发送。后端检查JPEG格式、字节与像素上限，不接受任意外部图像地址。调用当前支持图像的 `deepseek-flash`，使用 `thinking max`；只描述可见信息，不触发场景或设备动作，也不在数据库存图像。实际联调已获得道路、建筑、停车区描述和可核验巡检建议。

## 知识与验证形成可持续迭代基础

二期知识库沿用并更新原有5篇业务指南，新增8篇数据、角色、道路图、联合推荐、工单、经营、语音视觉与评测文章，共13篇。新库使用独立代码 `smart-parking-agent-v2`，保留旧库，避免覆盖手工修改。检索限定停车域，继承座舱的结构化分块与混合检索，不搜索其他企业私有业务库。

本轮本地接口评测32项全部通过，覆盖授权、账本金额分区/按日一致性、协议生命周期、三条导览、工单流转与两次真实Flash规划。首个AG-UI事件在本地SSH联调中约63毫秒，两次自由规划总耗时约3.1秒和21.2秒；这些是样本观测，不是稳定延迟保证。截图问答另行验证，前端21项回归同时检查车辆朝向、轮胎转动和固定尾随。

UI使用园区原有蓝灰与青色，业务动词、状态色、40像素触控目标和清晰焦点替代装饰性面板。经营、工单、看图与审计都在同一按需浮层中，桌面与手机继续共享精细模型。下一步接入真实设备时，优先替换数据适配器、道路配置与现场制度，现有权限、协议、工作流和回归集可以继续保留。
