量化の初心者として、私が最初に得た達成感はネットアセットカーブ（純資産曲線）から来ていました。いくつかのウィンドウ、閾値、重みを調整するだけで、曲線は突然滑らかで急峻になることがあります。その瞬間、「規則性を見つけた」という錯覚に陥るのはとても簡単です。

後に、講座の中で出てきた一言が、私の判断の順序を変えました。**美しい曲線の前に、カンニングがないことを証明せよ。**

この一言は、バックテストを「結果」から「証言」へと格下げしました。証言は真実のこともあれば、悪気なく嘘をつくこともあります。そして私の仕事はそれを鑑賞することではなく、監査人のように反対尋問することです。以下は、私が今もっともよく使う問いかけです。

## 当日のシグナルで当日のリターンを得ることはできない

最も小さく、最もよく見かける未来関数は、たった `shift(1)` の差で生まれます。

今日の終値を使って移動平均のシグナルを計算するとします。このシグナルは今日の終値が確定した後でなければ完全には決まらないため、通常は翌取引日に保有するかどうかを決めることしかできません。もし今日のシグナルをそのまま今日のリターンに掛け合わせると、今日どれだけ上がったかを事前に知っていて、寄付前から保有していたかのように振る舞っているのと同じです。この種の誤りはエラーを出さず、曲線を醜くもしません。むしろ曲線を美しくするからこそ危険なのです。

今では、このようなロジックに対してとても小さなテストを書くようにしています。3〜5日分の価格を作り、シグナルが特定の一日の引け後にしか現れないようにしたうえで、戦略のリターンが次の期間からしか発生しないことをアサートします。テストに実際の相場データは必要なく、その価値は時間のセマンティクスを固定することにあります。示意的な擬似コードはおおよそ次のようになります。

```python
# 例示：シグナルは次の期間にしか作用できないことを検証する
import pandas as pd

price = pd.Series([10, 10, 11, 12, 13])          # 上昇はインデックス2で発生
raw_signal = (price > price.shift(1)).astype(int)  # 引け後に確定
position = raw_signal.shift(1).fillna(0)         # 肝心なのは1本ずらすこと
ret = price.pct_change().fillna(0)
strat = position * ret

# アサート：上昇はインデックス2なので、リターンはインデックス3以降でなければならない
assert strat.iloc[2] == 0
assert strat.iloc[3] != 0
```

もし後で誰かが発注ロジックをリファクタリングし、そのずらしをこっそり外してしまったら、このテストはすぐに赤くなります。それが守っているのはリターンではなく、時間の因果の向きです。

## 財務データの日付はひとつだけではない

年次報告の対象期間は12月31日かもしれませんが、市場が実際にそれを目にするのは翌年の3月かもしれません。バックテストで `report_date` だけを使っていると、1月の時点でまだ公表されていないデータを先取りして使ってしまう可能性があります。

そのため、財務データには少なくとも次の情報を同時に保持する必要があります。

- それがどの報告期間を表しているか（`report_period`）
- 市場がそれをいつ入手できるか（`available_at`）
- 出所は何か（`source`）
- 予告、速報、正式報告、修正版のいずれか（`revision`）

これらの列があれば、データ取得ロジックにひとつの硬い制約が生まれます。各評価日 `t` では `available_at <= t` のレコードだけに絞り込み、条件を満たす複数のバージョンのうち最新のものを取るのです。同じ報告期間はしばしば「予告 → 速報 → 正式 → 修正」と何度も更新されます。「最終値」ひとつだけを残すのは一見きれいですが、実際には後から知った数字を当時に押し戻していることになります。修正版はとりわけ厄介で、当時は誰も知らなかったより正確な数字を、過去の自分に前倒しで手渡してしまいます。

この「その時点で」（point-in-time）という制約はデータベースの細部のように見えますが、本質的には、実験の研究者が時間を超えていないかどうかを決めています。私はこれを分析時に思い出すフィルタではなく、ストレージ層のデフォルトの挙動にするようにしています。いったん忘れると、バックテストはエラーを出さず、ただ見栄えが良くなるだけだからです。

## グロスリターンは現実世界のものではない

手数料、印紙税、スリッページ、インパクトコストは、多くの高回転率戦略を「優秀」から「実行不可能」へと変えてしまいます。私はもうグロスリターンだけを見ることはせず、少なくとも次のようなコスト感応度を比較するようにしています。

1. 基本コストを前提とした結果
2. コストを倍にした場合の結果
3. リバランス頻度を下げた場合の結果
4. 回転率、リターン、最大ドローダウンがどのように連動して変化するか

これらの段は個別に見るのではなく、その連動を一緒に読むべきです。コストが倍になると、実際に削られるのは頻繁な売買で稼いでいた薄い利ざやです。だから純リターンは下がりドローダウンは深くなる一方、回転率そのものは変わりません。これはリターンが低摩擦の仮定に強く依存している証拠です。ここで私はさらに、コストは固定の定数ではないと自分に言い聞かせます。インパクトコストは発注規模と流動性によって変化し、小さな資金なら無視できるスリッページも、実運用の規模に拡大すると超過リターンをすべて食い尽くすのに十分なことがあります。リバランス頻度を下げるのは逆方向からの検証です。回転率を抑えてもリターンが崩れないなら、戦略の核心は出入りの手触りではなく保有そのものにあります。下の図は三つの段を並べたものですが、方向は連動を表すためのもので、実測値ではありません。

![コスト感応度のはしご：基本コスト、コスト倍、回転率低下の三段を並べ、リターン・最大ドローダウン・回転率の連動方向を示す](/images/trust-the-backtest-cost.svg)

もし戦略が極端に低いコストの仮定の下でしか成り立たないのであれば、それはデータの中の飾りに近く、これ以上時間をかけるべき研究仮説とは言えません。

## テストセットは繰り返し見るための解答用紙ではない

もうひとつ印象に残っている誤りは、テスト期間でパフォーマンスが良くないときにパラメータを修正し続けることです。たとえその都度の修正が理にかなっていたとしても、同じテスト結果を繰り返し覗き続けると、それは徐々にパラメータ選択に参加してしまい、もはや本当のサンプル外データではなくなります。この漏れには単一の「カンニングの瞬間」がなく、「もう一つ試そう」という何度もの繰り返しの中で静かに積み上がっていきます。

ウォークフォワードは私に、より厳格な手順を与えてくれました。各ウィンドウでは、訓練区間だけを使って候補パラメータを比較し、勝ち残ったパラメータを固定したあと、直後のテスト区間で一度だけ実行します。最終的な曲線は、各ウィンドウのテストリターンだけをつなぎ合わせたものになります。あるテストウィンドウで損失が出ても、その場でパラメータを変えることはできません。損失それ自体が証拠だからです。「選定」と「検証」の間に一つの錠をかけて初めて、その区間のリターンが私の後知恵に汚されていないと言えるのです。

訓練ウィンドウの長さ自体も、事後に微調整するのではなく事前に決めておくべきパラメータです。短すぎれば選ばれたパラメータは直近のノイズに当てはめただけになり、長すぎれば市場のスタイルの切り替わりをまたいでしまうかもしれません。私はこの選択もローリングのステップ幅とともにフローに書き込み、あらかじめ固定するようにしています。それがまた一つの、繰り返し探ってしまう隠れたつまみにならないようにするためです。

## 時間のほかにも、見落とされがちな覗き見がある

時間のセマンティクス以外にも、サンプルそのものが未来を覗き見ることがあり、しかもより見えにくいのです。

- **生存者バイアス**：銘柄ユニバースに今日もなお取引されている銘柄しか含まれていなければ、後に上場廃止や破綻に至った企業をあらかじめ取り除いていることになり、バックテストで生き残るのは勝者ばかりになります。
- **売買停止とストップ高・ストップ安**：シグナルはある日に買えと言うのに、その日がちょうど一本値のストップ高や売買停止で、現実にはまったく約定できないことがあります。バックテストが常に終値で約定できると仮定していると、最も激しい値動きを何もせず手に入れてしまいます。
- **ユニバースの先読み**：今日の業種分類、指数構成、時価総額順位を使って何年も前の銘柄選定をさかのぼるのは、今日になって初めて分かる分類を過去に押し戻すことです。

これらの罠に共通するのは、どれもバックテストを現実より寛容にすることです。そして寛容さの向きは、いつも美しい曲線のほうを向いています。

## 私は今、どのようにカーブを読むか

結果を目にしたとき、私はまず次のように問いかけ、その問いの背後にある失敗モードを一つずつ明確にします。

- シグナルと取引は、正しい時間だけずれているか。——ずれていなければ、未来関数が当日を覗いています。
- 財務、ニュース、銘柄ユニバースは、その時点で利用可能なバージョンを使っているか。——違えば、時点漏れか先読みです。
- 十分に保守的な取引コストを織り込んでいるか。——織り込んでいなければ、グロスリターンが実行可能性を過大に見せています。
- パラメータのグリッドは実験前に固定されていたか。——違えば、私はテストセットで調整しています。
- 最終的な結果は、選択に関与しなかったデータだけから得られているか。——違えば、「サンプル外」は名ばかりです。
- ドローダウン、回転率、ウィンドウ別のパフォーマンス、失敗した局面も同時に報告されているか。——滑らかな曲線を一本だけ示すのは、たいてい何かを隠しています。

量化を学んだあと、私はモデルを信じるのが上手くなるのではなく、むしろモデルが困るような問いを立てるのが上手くなりました。これは進歩だと感じています。バックテストは自分の賢さを証明するためのものではなく、自分がどこで間違えうるかを早期に見つけるためのものなのです。私が信じてもよいと思う曲線は、たいてい最も急なものではなく、上のすべての問いに繰り返し尋問されてもなお立っていられるものです。
