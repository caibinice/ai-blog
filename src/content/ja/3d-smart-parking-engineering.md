駐車場の3D画面では、園区を素早く開き、空き状況を理解し、必要なエリアへ移動できることが大切です。見た目とともに、アセット、業務状態、入力、配信の境界を設計する必要があります。

AngularとBabylon.jsを使った既存の病院園区プロジェクトを、名称を匿名化した独立フロントエンドのデモへ整理しました。さらに専用の軽量モバイルページを追加しています。

[デスクトップ版](/smartParking/) · [モバイル版](/smartParking/mobile) · [GitHubソース](https://github.com/caibinice/3dSmartParking)

![スマート駐車場3Dワークスペース](/images/project-parking.png)

## アセット予算から優先順位を決める

元のアセットディレクトリは約616MBでした。三つの園区モデルは合計約479MBで、既定のGLBだけで164,807,820バイトあります。開始動画、監視動画、アニメーション画像、多数の重複コンポーネントも含まれていました。

今回、Angular18から21.2.25、Babylon.js7から9.29.0へ更新し、純粋なデータ関数、signalsストア、描画クラス、表示コンポーネントへ分割しました。ルートと3Dエンジンは遅延読み込みです。公開GLBは7,089,576バイトとなり、約95.7%削減できました。モバイル版はGLBを要求せず、低ポリゴンの代表的な園区をコードで生成します。

## 名称変更はモデルも対象になる

HTMLのタイトル変更だけでは、建物の文字形状は変わりません。看板はジオメトリであり、画像テクスチャにも識別情報が含まれる可能性があります。

変換時に元の文字ノード、高精細車両、画像テクスチャ、アニメーション、遠景の大きな平面を取り除きます。ノード、メッシュ、マテリアルの名前も一般化しました。画面は「某某公司」「某某医院」、DynamicTextureで生成する看板は「某某中医院」です。元の開始動画、監視動画、固定監視アドレスは公開対象から外しています。元アセットは外部ローカルバックアップに保存しました。

glTF Transformを使い、重複排除、頂点の溶接、形状簡略化、未使用データ除去を再現可能な処理にまとめました。

```javascript
await document.transform(
  dedup(), weld(),
  simplify({ simplifier: MeshoptSimplifier, ratio: 0.15, error: 0.001 }),
  prune()
);
```

小さな誤差予算で主要な建物形状を維持し、車両はプログラムによるインスタンスへ置き換えます。公開モデルに埋め込み画像はありません。追加の遠隔デコーダーを必要とせず、Nginxの事前gzip圧縮で転送量も減らします。

## 占有数を同じデータから導出する

容量、占有数、空き数、推奨エリア、3D上の比率は一つの状態を参照します。総容量は300。5秒ごとに一台分の入出庫をシミュレーションし、各エリアの占有数をゼロと容量の間に収めます。

```typescript
const capacity = zones.reduce((sum, zone) => sum + zone.capacity, 0);
const occupied = zones.reduce((sum, zone) => sum + zone.occupied, 0);
const free = capacity - occupied;
```

3000回の更新テストで境界と保存則を確認しています。3Dの駐車枠は占有比率の表現であり、全300枠を個別に再現するものではありません。正確な数値はパネルが示します。

エリア移動、全景・俯瞰、巡航、通知の確認、入出庫履歴の検索とCSV出力、空きが多いエリアの推薦を追加しました。指標、記録、通知はシミュレーションであることを明示し、実際のゲート、カメラ、料金設備とは接続していません。

## 描画と業務更新を分離する

ParkingSceneがエンジン、カメラ、メッシュ、入力、解放を管理します。AngularはZone.jsを使わず、業務更新と毎フレームのscene.renderを切り離します。

駐車枠と車両はそれぞれ一つのthin-instance元メッシュを共有します。占有状態が変化した時だけ行列を更新するため、毎フレーム大量の業務オブジェクトを生成しません。

ResizeObserverでキャンバスサイズを追跡し、非表示タブでは描画とデータ更新を止めます。ルート離脱時にはエンジン、シーン、タイマー、監視オブジェクト、タッチリスナーを解放します。非同期モデルの完了時にも、既に破棄されたシーンかどうかを確認します。

## WebGPUと画質制御

既定はWebGLで、`?renderer=webgpu`を付けるとWebGPUを選択できます。機能確認と初期化はシーン資源を作成する前に行い、対応しない環境ではWebGLを使用します。

新しい描画バックエンドと、アセット削減、インスタンス化、ライフサイクル管理は一緒に設計すべきです。WebGPUだけで大容量ダウンロードや重複オブジェクトの負担が消えるわけではありません。

自動、高画質、均衡、低消費電力の四段階を用意し、devicePixelRatioを上限で制御します。目標はデスクトップ60fps、モバイル30fps。自動モードでは実際の描画速度が低い場合に解像度を下げます。FPS表示はRAF通知数ではなく、描画されたフレームを数えています。真機の速度はGPU、発熱、電池状態に応じて追加測定するものです。

## モバイルの横向きとタッチ操作

独立した`/mobile`ルートは、箱形の建物と階層ラインによる軽量園区を生成します。エリアの意味はデスクトップと共通ですが、細部を減らし、主な操作ボタンは44px以上にしました。

全画面操作後にシステムの横向き固定を試みます。ブラウザが方向固定を制限している場合でも、縦向きではCSSで横向きワークスペースを表示します。この時は入力座標も逆変換が必要です。

```typescript
const point = portrait
  ? { x: event.clientY - rect.top, y: rect.right - event.clientX }
  : { x: event.clientX - rect.left, y: event.clientY - rect.top };
```

一指で回転し、二指の距離で拡大縮小します。カメラの距離と角度には境界を設定し、エリアボタンによる精密な移動も用意しました。横向き・縦向きの両方で、スクロール境界、ボタンの表示、GLB要求がゼロであることを確認します。

## 静的配信と検証

本番のbase hrefは`/smartParking/`で、Nginxは`/smartParking/mobile`の直接アクセスにも対応します。モデルが欠落した時はブログHTMLを返さず404とし、アプリでは軽量園区へフォールバックします。エンジン初期化に失敗した場合は再試行を表示します。

タイムスタンプ付きreleaseへ配置して、シンボリックリンクを原子的に切り替えます。設定をバックアップし、nginx -tで検証してからreloadします。失敗時には旧設定と旧releaseを戻します。指紋付きJS/CSSは長期キャッシュ、HTMLは再検証、モデルは短期キャッシュです。

型検査、データテスト、名称・テクスチャ監査、productionビルド、実際のHTTPSページ確認までを一つの工程にまとめました。ブログにもプロジェクト入口、実画面、三言語の技術記事を追加しています。
