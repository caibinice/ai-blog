精細な園区モデル、車両巡行、回転するタイヤと固定距離の追従カメラを維持しながら、今回は業務機能を拡張しました。対話と業務台は必要な時だけ表示するオーバーレイです。全画面キャンバスを縮小せず、バックエンドも既存の企業AIコックピットのSpring Boot、MySQL、pgvector、知識検索を再利用しています。

## 再現可能な年間合成台帳

現地の機器データを収集する代わりに、[UCI Parking Birmingham](https://archive.ics.uci.edu/dataset/482/parking%2Bbirmingham)の公開観測から日内の規則を抽出しました。元データはBirmingham City Council/NCPに由来し、Daniel Stolfiが整理した2016年の部分的な昼間観測です。完全な終日系列ではありません。リポジトリには出典、原ファイルのハッシュとライセンス説明を保存しています。

不正な容量と占有数を除去し、平日・週末別の十五分スロットを集計します。夜間は明示した合成曲線を使い、季節変動、区画係数と固定乱数シードを加えて、**2025-10-03から2026-10-02まで365日**に拡張しました。

| データ | 件数 | 用途 |
|---|---:|---|
| 区画別占有スナップショット | 105,120 | 空き台数・利用率 |
| 匿名駐車記録 | 167,906 | 入出場・滞在・料金台帳 |
| 合成アラート | 365 | 巡回・作業票の検証 |

容量はA120、B100、C80です。各時点は次の保存則を満たします。

```text
今回の占有 = 前回の占有 + 入場 - 出場
0 <= 占有 <= 容量
```

入場時に匿名記録を作成し、出場時に精算します。金額は整数の分単位で保存し、別途定義した合成料金規則を適用します。公開元には料金台帳がなく、合成料金は実在病院の料金ではありません。収入は精算済みの `paid_cents` から集計します。

```sql
SELECT COUNT(*) AS settled_stays,
       COALESCE(SUM(paid_cents), 0) AS paid_cents
FROM parking_stays
WHERE dataset_id = 'parking-year-v1'
  AND exited_at >= :from
  AND exited_at < :to_exclusive;
```

SHA256、シードと期間を記録し、同じ入力で同じ結果を生成します。取り込み前にDBをバックアップし、不変データセットIDと冪等キーを使い、件数を検証します。画面には合成データの出所と採取時刻を表示し、過去値を現場のリアルタイム値として扱いません。

## サーバーで強制する役割権限

GETを含む全駐車APIが署名付きユーザーを確認し、業務アカウントの役割はDBでも再確認します。パスワードはBCryptハッシュ、セッションは三十分です。

| 役割 | 業務 |
|---|---|
| 訪問者 | 空き台数、推薦、POI、経路、訪問者ガイド |
| 警備 | アラート、入出場、作業票、確認済み画像質問 |
| 運営 | 料金台帳、期間レポート、全体監査、承認・終了 |
| 管理者 | アカウント、知識初期化、道路グラフ設定 |

訪問者の自由質問はローカル知識を利用し、有料モデルを呼び出しません。業務ユーザーはFlashとthinking maxを既定とし、認証後のProも選択できます。ブラウザー内のroleを書き換えても権限は上がらず、停止したアカウントの役割トークンは無効になります。

## POIグラフで推薦と経路を接続

モデルは任意座標ではなく安定したPOI IDを出力します。グラフは点位、種類、区画、モデル座標、設備能力、閉鎖状態を保存します。設定保存ではIDの重複、有限座標、道路端点とバージョンを検証します。

Dijkstraは開放された点位と道路だけを探索します。距離はモデル比率からの推定値です。閉鎖や非連結なら明示的に失敗し、建物を横切る架空経路を描きません。管理者がグラフを更新でき、後から測量データへ交換できます。

推薦は満車、閉鎖、到達不可、条件不一致を除外し、徒歩距離、空き台数と急診用合成予約枠で順位をつけます。充電条件はB区、急診条件はC区を選択し、通常要求ではC区に十台分を残します。距離、空き、予約枠と理由を表示します。設備は区画単位のデモ設定で、個別センサー情報ではありません。

## 人工確認を含む作業票

`workorder.prepare` は下書きだけを生成します。担当者がアラートと備考を確認し、チェックボックスで送信を承認してからDBに書き込みます。

```text
審査待ち → 運営承認 → 警備が担当 → 核認完了 → 運営終了
```

要求キーと未終了作業票の確認で重複を抑え、トランザクションとバージョンで競合を防ぎます。モデルに承認回避やゲート制御のツールはありません。監査の `client-result` はブラウザーの実行報告であり、現場機器の応答ではありません。

## 料金台帳から経営分析

期間と区画を指定し、容量加重の日平均占有率、精算件数と合成受領額を表示します。CSVには全日次集計を含め、画面の十八行はプレビューに限定します。

![年間合成台帳の分析](/images/parking-agent-year-report.png)

日・週・月・年レポートはデータセットの最終日を基準にします。月はその月の初日から最終データ日まで、年は全365日です。既存コックピットプロセスが **Asia/Shanghai 02:15** に四種類の集計キャッシュを生成します。DB集計のみでモデルを呼ばず、対象期間と生成時刻を保存します。

## AG-UIと制御ツール

`/api/parking/ag-ui` は標準の実行、テキスト、ツール呼び出し、状態スナップショットを出力します。業務レポート、経路、作業票下書きと参照はCUSTOMイベントです。フロントは公式 `@ag-ui/core` schemaで全イベントを検証してから許可リストに従って実行します。

```json
{
  "type": "TOOL_CALL_ARGS",
  "toolCallId": "action-0",
  "delta": "{\"target\":\"outpatient\"}"
}
```

実装対象は本システムが実際に生成するイベント集合です。未実行のツール結果を捏造しません。SSEではNginxのバッファとキャッシュを無効にし、キャンセル後のシーン操作を止めます。一回答内で複数レポートも保持できます。

## 音声と画像の明示的操作

単発、ウェイクワード、連続音声モードを用意しました。連続モードは処理中も聞き取りを保ち、読み上げ中に中国語のウェイクワードを発すると中断できます。自身の読み上げ文字列との照合でエコー誤動作を減らします。マイクは既定でオフ、バックグラウンド移行で停止します。

SpeechRecognitionとspeechSynthesisはブラウザー機能であり、実際の認識は対応状況、マイクとネットワークに依存します。イベント回帰テストは中断・停止・解放を確認しますが、真人の認識精度を示すものではありません。

画像質問は3Dキャンバスをプレビューしてから担当者が送信を確認します。チャットやアカウント欄は画像に含めません。バックエンドはJPEG、バイト数と画素数を検証し、外部画像URLを受け入れません。画像対応の `deepseek-flash` とthinking maxを使い、可視情報だけを説明し、ツールを起動せず画像もDB保存しません。実際のAPI連携で道路、建物、駐車区画の説明と確認可能な巡回提案を得ました。

## 知識と回帰テスト

二期知識庫 `smart-parking-agent-v2` は既存五記事を更新し、データ、権限、道路図、推薦、作業票、経営、音声画像、評価の八記事を追加した計十三記事です。旧知識庫は保持し、他業務の私有文書には検索を広げません。構造化分割とハイブリッド検索はコックピットを継承します。

ローカルの三十二API・業務ケースはすべて成功し、実際のFlash計画二件も含みます。SSH連携サンプルでは最初のAG-UIイベントが約63ミリ秒、全処理が約3.1秒と21.2秒でした。これは観測値であり遅延保証ではありません。画像質問を別途検証し、フロント二十一回帰で車両方向、タイヤ回転と固定追従も維持しています。

UIは元の青灰色とティールを使い、業務動詞、明確なフォーカスと四十ピクセルのタッチ目標を重視しました。デスクトップ・スマートフォンとも精細モデルと全画面感を保持しています。今後の現場接続はデータアダプター、測量グラフ、運用規則を交換し、権限、プロトコル、業務フローと回帰集を再利用する方針です。
